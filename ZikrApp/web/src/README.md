# Web build sources

- `app.html` – the app shell, styles and logic
- `hisn.json` – **generated** by `build_hisn.py`: Hisn al-Muslim (Fortress of the Muslim) from the sunnah.com
  data, Arabic / transliteration / translation / reference exactly as published
- `names.json` – **generated** by `build_names.py`: the 99 Names as listed in Jami` at-Tirmidhi 3507 (sunnah.com)
- `reflections.js`, `more_topics.js` – reflection topics (title, verse reference, hadith reference, art).
  Only the references are used: the verse, hadith and tafsir texts are pulled, and the reflection
  paragraph is written live by Claude (artifact `sample` capability) from those pulled texts only.
  Without it, the page shows the Al-Mukhtasar tafsir of the verse instead.
- `art.js` – animated illustrations (shapes only, no faces)
- `sources.js` – **generated**: authentic Quran and hadith text for every reference

## Refreshing authentic texts

`sources.js` is produced by `pull_sources.py` from:
- Quran: the npm package `quran-json` (Uthmani text from QuranEnc / King Fahd Complex,
  Saheeh International English, Tanzil transliteration)
- Hadith: the npm package `hadith` (the sunnah.com collection data: Arabic, English, grading)

```bash
npm pack quran-json@3.1.2 && tar xzf quran-json-3.1.2.tgz -C qj
npm pack hadith && tar xzf hadith-*.tgz -C hadith
python3 pull_sources.py . qj/package/dist hadith/package/data/hadith.db sources.js
python3 build_hisn.py hadith/package/data/hadith.db hisn.json
python3 build_names.py hadith/package/data/hadith.db names.json
python3 build.py   # writes the single-page app
```
The script keeps each cited hadith number and prints any whose wording differs a lot
from the summary, so they can be checked by hand.

## Quran reader

`quran.js` (the whole Quran for the reader) is generated by `build_quran.py`: Arabic and English from `quran-json`, transliteration from Quran.com's word-by-word data (standard scheme: dh, th, ʿ, ā ī ū):

```bash
npm pack @kmaslesa/holy-quran-word-by-word-full-data && tar xzf kmaslesa-holy-quran-word-by-word-full-data-*.tgz -C wbw
python3 build_quran.py qj/package/dist wbw/package/data.json quran.js
```

## Tafsir (loaded on demand)

The reader's tafsir view fetches `tafsir/{ik|mx}/{surah}.json` next to the page. These files are
**not committed** (Tafsir Ibn Kathir's English edition is a copyrighted publication); rebuild them with:

```bash
for ed in en-tafisr-ibn-kathir en-tafsir-al-mukhtasar; do mkdir -p taf/$ed
  for s in $(seq 1 114); do curl -sSf -o taf/$ed/$s.json \
    https://raw.githubusercontent.com/spa5k/tafsir_api/main/tafsir/$ed/$s.json; done; done
python3 build_tafsir.py taf ../tafsir
```
Source: spa5k/tafsir_api (data from Quran.com / Tarteel QUL). `ik` = Tafsir Ibn Kathir (abridged
English), `mx` = Al-Mukhtasar (Tafsir Center for Quranic Studies). Ibn Kathir's repeated passages are
stored once per surah (`p`) with a per-ayah index (`m`).

## Bangla (switch with the বাং / EN button)

All Bangla text is a published translation; nothing is translated by hand.

- `quran_bn.json` – Abu Bakr Zakaria's Bangla Quran translation (King Fahd Complex), from
  fawazahmed0/quran-api `ben-abubakrzakaria`; only footnote markers like [১] are removed
- `hadith_bn.json` – Bangla text of each hadith in `sources.js`, from the Bangla editions in
  fawazahmed0/hadith-api. `match_hadith_bn.py` finds each hadith by its Arabic text (Sahih Muslim is
  numbered differently there), skips "same hadith through another chain" entries, and starts at the
  hadith's own number where the edition puts chapter notes first. Two have no usable Bangla text and
  show in English.
- `hisn_bn_titles.json` – Hisn al-Muslim chapter titles from hisnmuslim.com. The site has no Bangla
  text for the duas themselves, so their meanings stay in English.
- Tafsir `zkb` (Tafsir Abu Bakr Zakaria) and `mxb` (Bengali Al-Mukhtasar) from spa5k/tafsir_api.
  The Bangla Ibn Kathir (5.7 MB compressed) does not fit within the page's 16 MB limit.

```bash
curl -o zak.json https://raw.githubusercontent.com/fawazahmed0/quran-api/1/editions/ben-abubakrzakaria.json
curl -o bn27.html https://hisnmuslim.com/i/bn/27
# tafsir: download bn-tafsir-abu-bakr-zakaria and bengali-mokhtasar like the English ones, into tafbn/
python3 build_bn.py zak.json bn27.html tafbn .        # writes quran_bn.json, hisn_bn_titles.json, tafsir/{zkb,mxb}
# hadith: download {ara,ben}-{bukhari,muslim,tirmidhi,abudawud,ibnmajah}.json from fawazahmed0/hadith-api into hbn/
python3 match_hadith_bn.py sources.js hbn hadith_bn.json
python3 build.py
```
All tafsir editions are embedded in the page gzipped per surah and unpacked when a surah is opened.

## Prayer times and adhan

- `adhan.umd.min.js` – adhan.js 4.4.6 by Batoul Apps (MIT), from npm `adhan`; calculates the times on the device.
- `cities.json` – 7,281 cities with coordinates and time zones from npm `city-timezones` 1.3.4 (MIT),
  as `[name, country, lat, lng, tz]`, largest first. Used to guess the place from the time zone and for city search.
- `adhan.mp3` – "Beautiful adhan" by Adam-synagda on Wikimedia Commons (CC0), re-encoded to 32 kbps mono MP3
  with `ffmpeg -i Beautiful_adhan.ogg -ac 1 -ar 22050 -b:a 32k adhan.mp3` so iPhones can play it.

The adhan plays while the page is open. Browsers stop pages that are closed or in the background, so a
web page can't sound the adhan then; that needs an installed app.

## Installable app (GitHub Pages)

`python3 build_site.py` (after `build.py`) writes `ZikrApp/app/`: the page wrapped in a full HTML
document with the app icon (`site/icon.svg`, PNGs rendered from it), `manifest.webmanifest`, and `sw.js`, a service
worker that keeps the app on the phone so it opens offline and picks up updates on the next launch.

Serve it with GitHub Pages ("Deploy from a branch", folder `/ (root)`); it is then at `https://<user>.github.io/<repo>/ZikrApp/app/`.
On iPhone open that link in Safari, tap Share → Add to Home Screen.

Off claude.ai the page has no access to Claude, so reflections show the Al-Mukhtasar tafsir instead of a written reflection.

## More dhikr from Hisn al-Muslim's narrations, and more Quran duas

- `hisn_virtues.json` (by `build_hisn_virtues.py`): the dhikr Hisn al-Muslim quotes inside its narrations
  ("Whoever says … a hundred times"), as counters. The book marks the words to say in brackets; the Arabic is
  the bracketed text from sunnah.com, the transliteration, meaning and repeat count come from hisnmuslim.com's
  English edition (`https://www.hisnmuslim.com/api/en/<chapter>.json`). The full narration shows as the source.
  E.g. #256 "SubhanAllahi wa bihamdihi, SubhanAllahil-'Azim", #259, #260 (la hawla…), #261.
- Duas from the Quran: the "Rabbana" duas and the duas of the prophets (55 entries), whole ayahs.
- Search folds spellings together (th/dh/z/zh, aa/ee/oo, w/u) and matches word by word.

## Duas and dhikr from hadith (no transliteration needed)

- `hadith_lib.json` (by `build_hadith_lib.py`), embedded gzipped and loaded just after the page starts:
  - **HadeethEnc.com** (Encyclopedia of Translated Prophetic Hadiths), 140 hadiths from "Supplications and
    remembrance of Allah", "Merits of supplication" and "Dhikr during prayer"
    (`https://hadeethenc.com/api/v1/hadeeths/one/?language=en|bn&id=<id>`): Arabic, English and Bangla, the
    narrator, grade, explanation and lessons, exactly as published. Ruqyah was left out. When the hadith quotes the
    dua in so many words (after "he used to say: «…»"), the counter shows that quote, Arabic and English as written
    in the hadith; otherwise it shows the whole hadith.
  - **Sahih al-Bukhari, Book 80 (Invocations)** and **Sahih Muslim, Book 48 (Remembrance, supplication,
    repentance)**, 233 hadiths with the chain, from the sunnah.com data; Bangla from fawazahmed0/hadith-api's
    Bangla editions where it matches by the Arabic (192).
- Home shows **Today's dua and its hadith** under Today's zikr. It alternates daily between a HadeethEnc hadith and a Hisn al-Muslim dua (with the narration and reference the book gives), and every Friday shows Sayyid al-Istighfar with its full hadith from Sahih al-Bukhari 6306 (counted as Hisn al-Muslim 79, the same words). HadeethEnc days show the
  full hadith, its Arabic, grade, and "Explanation & lessons". Discover → "Duas & dhikr from hadith" lists them all.
- To keep the page under 16 MB the city list is now embedded gzipped too (one city per time zone is kept plain
  for the first moment after start).

## Backup and restore

Stats → Backup: "Save backup" writes everything the app keeps (the whole saved state) to `zikr-backup-<date>.json`,
through the iPhone share sheet (Save to Files / iCloud Drive) where available, else as a download.
"Restore from file" reads such a file, asks before replacing, and reloads.

## Hourly Quran

Home → "Hourly Quran": a portion of ayahs (13 by default) for every waking hour (6 AM–10 PM by default, 16 hours),
so 13 × 16 × 30 ≈ 6,236 ayahs: the whole Quran in about 30 days. Each waking hour that starts adds a portion; a missed
hour waits and the next hour's portion is added on top, until everything up to the current hour is read
("You're current"). Reading ahead counts toward the next hours. The plan keeps its own place in the Quran
(free reading keeps its own), only the plan's next ayah counts when swiped, and a plan started mid-Quran runs on
from An-Nas to Al-Fatihah. Changing the settings keeps what is owed and counts the new settings from the next hour.
The reader has an Hourly / Normal switch. In hourly mode the reader stops once you are current ("You're current",
with the next portion's time and ayahs); "Read ahead" lets you swipe on, and each hour finished ahead is marked green.
In the iPhone app a local notification comes at the start of each waking hour that still needs reading (ids 9000+,
about two days set ahead and set again whenever the app is opened or left), so hours read ahead get no reminder;
tapping it opens the hour's portion. The web page can't notify while closed; it shows the portion when opened.
The card lists the current hour, this hour's portion and what is left of it, the missed ayahs and hours, where to
start and the ayah to read up to; a strip of today's waking hours marks each hour read (green) or not read (red); the current hour is outlined, green when current and red when not.
The reader marks the last ayah of the portion. The waking hours button on the card opens the settings.
